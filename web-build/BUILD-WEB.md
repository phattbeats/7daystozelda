# Rebuilding the web version from source

Everything needed to reproduce `public/` from upstream code.

## Sources

- Base: https://github.com/bghill95/OOT-True-Co-op @ `b738c76`
- `OOT-True-Co-op/` — 8 patches on the repo:
  1. Linux/GCC header fix
  2. Nearest-player enemy targeting
  3. Enemy sound/effect sync, horde night, review fixes
  4. Web build (WebAssembly + Anchor over WebSocket)
  5. Web lobby UI, extraction fix, settings persistence, connection resilience
  6. Web mobile pass (ROM import, install, touch/controller, app-switch handoff)
  7. Fix in-browser ROM extraction and the WebGL texture-table overflow (#3860)
  8. Web audio: deeper buffers, underrun recovery
- `libultraship/`, `ZAPDTR/`, `OTRExporter/` — patches on each submodule's pinned commit (zalo/shipwright-64's Emscripten commits, conflicts resolved for these versions).

```sh
git clone --recursive https://github.com/bghill95/OOT-True-Co-op && cd OOT-True-Co-op
git checkout b738c76 && git submodule update --init --recursive
git am ../src/OOT-True-Co-op/*.patch
for r in libultraship ZAPDTR OTRExporter; do (cd $r && git am ../../src/$r/*.patch); done
```

Patch 4 records submodule pointers to commits that only exist on the build machine. That doesn't matter for building (the submodule working trees are what compile); to make the superproject consistent afterwards, run `git add libultraship ZAPDTR OTRExporter && git commit`.

## Build

Needs emsdk **3.1.64**, CMake ≥ 3.26, Ninja, and **~12 GB of RAM+swap** for a first build: the randomizer's table sources take 5+ GB each to compile under emcc. After that, changes outside those files are an incremental compile plus a ~30 s relink with no swap needed, so keep the build tree around.

```sh
source /path/to/emsdk/emsdk_env.sh
emcmake cmake -S . -B build-web -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_REMOTE_CONTROL=OFF -DUSE_OPENGLES=ON -DGFX_DEBUG_DISASSEMBLER=OFF -DSUPPRESS_WARNINGS=ON

# heavy files one at a time, then everything else
cd build-web
ninja -t targets all | grep -oE "soh/CMakeFiles/soh.dir/soh/Enhancements/randomizer/(3drando/hint_list[^:]*|location_list|item_list|settings|ShufflePots|randomizer)\.cpp\.o" | sort -u | xargs ninja -j1
ninja -j4 soh
```

Output: `build-web/soh/soh.{html,js,wasm,data}` → copy to `public/` (`soh.html` as `index.html`). The icons (`icon.svg`, `icon-*.png`) and the manifest (generated by `server.js`) live only in the bundle. `soh.o2r` comes from a normal desktop build (`cmake --build build --target GenerateSohOtr`); it holds only SoH's own assets.

`soh/soh/web/shell.html` is not a link dependency: after editing only the shell, `rm build-web/soh/soh.html` so ninja relinks (about 30 s).

Don't compile the heavy files at `-O0` to save memory: the result links into functions with more than 50,000 locals, which browsers refuse to load.

## Desktop builds

All web changes sit behind `__EMSCRIPTEN__` / `BUILD_FOR_WEB`; the normal desktop/Windows builds (and the fork's GitHub Actions) are unaffected.

## Debugging crashes

The release link keeps function names (`--profiling-funcs`), so a crash in the browser console prints a readable stack. For more, relink (no recompile) with `-sASSERTIONS=1` and optionally `-sSAFE_HEAP=1` added to the web `target_link_options` in `soh/CMakeLists.txt`.
